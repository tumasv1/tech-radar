# AI-радар Михаила Тумасова

Личный технологический радар: чем владею, что использую и что держу на прицеле. Радар описан кодом (markdown + git) и правится вручную или через Claude Code. Рендерится статическим сайтом [AOE Technology Radar](https://github.com/AOEpeople/aoe_technology_radar).

## Устройство

**Источник правды** — markdown-файлы в `radar/<дата-релиза>/<технология>.md`:

```markdown
---
title: "LangGraph"
ring: confident          # confident | using | wishlist
quadrant: ai-ml          # см. список секторов ниже
tags: [agents]           # см. допустимый список тегов ниже
---

**Знаком с:** 2026-03

Описание опыта с технологией.
```

- **Кольца (уровень владения):**
  - `confident` — Владею: уверенно применяю, могу объяснить устройство и показать результаты с метриками.
  - `using` — Использую: рабочий уровень, включая активное изучение прямо сейчас (курсы, первые применения).
  - `wishlist` — ХОЧУ: на прицеле, радар работает как напоминание.
- **Секторы (области компетенций):**
  - `ai-ml` — AI / ML: RAG, агенты, оценка LLM, голос, ML-техники и фреймворки.
  - `infra-data` — Инфраструктура и данные: БД, векторные хранилища, self-host, observability, очереди, LLM-инфраструктура.
  - `development` — Разработка: языки, фреймворки и инструменты написания кода (Python-стек, тесты, сборка, CI).
  - `product-management` — Продукт и управление: AI-продукт, управление командой/процессами, аналитика, enterprise-системы.
- **Теги** (сквозной фильтр по AI-поддоменам, использовать только эти значения):
  `agents` · `rag` · `voice` · `eval-observability` · `other`.
  Теги — отдельная ось от секторов: они помечают AI-поддомен независимо от того, в каком секторе технология (напр. Qdrant в секторе `infra-data` с тегом `rag`). Всё, что не попадает в agents/rag/voice/eval-observability, получает `other`. Как правило один тег на технологию. Не придумывать новые теги без явного запроса — список закрытый.
- **История:** чтобы зафиксировать изменение уровня, скопируй файл технологии в новую папку-релиз `radar/YYYY-MM-DD/` и поменяй `ring` — на странице технологии появится таймлайн.
- **Дата знакомства:** строка `**Знаком с:** YYYY-MM` в теле файла.

## Сборка и просмотр

```bash
npm install
npm run build   # → ./build
npm run view    # поднимает сервер на :8301 и сразу открывает страницу в браузере
```

`npm run view` — раскладывает `build/` в `/tmp/tech-radar-preview/tech-radar/` (сайт
живёт под `basePath: /tech-radar`, как на GitHub Pages), поднимает сервер на :8301 и
сама открывает `http://localhost:8301/tech-radar/` (macOS `open`). Сервер уходит в
фон — остановить: `pkill -f "http.server 8301"`.

Публикуется на **GitHub Pages** — автодеплой через `.github/workflows/deploy-pages.yml`
при каждом `git push` в `main` (ничего вручную запускать не нужно). Live:
https://tumasv1.github.io/tech-radar/

Конфиг квадрантов/колец/подписей — `config.json` (там же `basePath`/`baseUrl` под
GitHub Pages — не менять без необходимости), страница «О радаре» — `about.md`.

## Типовые операции

- **Добавить технологию:** создать `radar/<сегодня>/<slug>.md` с frontmatter выше — один сектор и один тег из закрытых списков.
- **Повысить уровень:** скопировать md в `radar/<сегодня>/`, изменить `ring` (только confident/using/wishlist).
- **Пересобрать:** `npm run build`.
- Синхронизация с профилем/резюме — вручную, радар не привязан к другим документам автоматически.
